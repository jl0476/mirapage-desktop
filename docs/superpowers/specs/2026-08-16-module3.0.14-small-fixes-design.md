### B. webdav `parse_propfind` 修复

`src-tauri/src/source/webdav_impl.rs`。两个根因（实测确认：解析返回 0 条，期望 2 条）：

1. **命名空间前缀**：测试 XML 用 `<d:response>` 等带前缀标签；`e.name().as_ref()` 拿到的是含前缀全名（`d:response`），与 `"response"` 比较永不命中。修法：加 `local_name()` 辅助（按第一个 `:` 切掉前缀，无前缀原样返回），Start/End 事件的匹配全部改用 local name。无前缀 XML（部分服务器）天然兼容。
2. **collection 检测**：`<d:collection/>` 是自闭合 Empty 事件，不是 Text 事件；现实现靠 Text 内容 `contains("collection")` 永远为 false。修法：新增 `Event::Empty` 分支——local name 为 `collection` 且 `current_field == "resourcetype"` 时对当前 PartialEntry 置 `is_collection = true`；同时 Start 分支同样处理 `<d:collection></d:collection>` 展开写法。

测试：现有红用例 `parse_propfind_extracts_collection_and_files` 转绿（TDD 驱动，保留其**前缀 + 自闭合** `<d:collection/>` 写法）；新增**无前缀 + 展开式** `<collection></collection>` 用例——两条 collection 解析路径（Empty 事件 / Start+End 事件）各有回归保护。

### D. 重置阅读进度修复

**现状两个叠加 bug**：`list_library` SQL 只返回 `is_favorite=1`（非收藏书查不到，重置悄悄失败）+ `RowContextMenu.onResetProgress` 只比 `rootPath`（同根多本书认错人）。

**新 Rust 命令** `reset_progress_by_location`（放 `src-tauri/src/commands/progress.rs`，`mark_finished` 同文件）：

```rust
#[command]
pub fn reset_progress_by_location(
    db: tauri::State<crate::db::Db>,
    source_descriptor: SourceDescriptor,
    abs_path: String,
) -> Result<bool, String>
```

- 匹配：复用 3.0.13 `find_next_volume.rs::sibling_is_finished`（line 197）的模式——descriptor 序列化比对 + `algorithm::path::validate_source_relative` 归一路径。**提取 `pub(crate)` 共享 helper** `find_library_id_by_location(conn, descriptor, abs_path) -> Option<i64>`，放 `commands/library.rs`（按位置查 library 行属 library 域），D/E 两命令共用；`sibling_is_finished` 是否改用该 helper 以改动最小为准（不强制）。
- 命中：`UPDATE progress SET page=0, image_name=NULL, finished=0, updated_at=now WHERE book_id=?1`，返回受影响行数 > 0；无 progress 行（从未读过）返回 false——**不做 upsert**，无行即无可重置。
- 未命中（library 无此书）：`Ok(false)`，不创建任何行。

**前端**：`lib/tauri.ts` 加 `resetProgressByLocation(descriptor, absPath)`；`RowContextMenu.onResetProgress` 整段重写——删 `library.refresh()` + rootPath 匹配逻辑，改单次 IPC。**absPath 按 entry 类型区分**（reset-progress 按钮无 `v-if`，图片右键同样显示；library 行的身份是其所在阅读目录，不是图片文件）：

- 目录项：`PathUtils.join(fb.lastFetchedPath, entry.path)`（entry.path 相对 lastFetchedPath）
- 图片项：`fb.lastFetchedPath` 本身（书 = 图片所在目录）

调用后无论 true/false 均 `readStatus.refresh()` + `emit('close')`；false 仅 log（与现行为一致，不 toast）。组件测试新增「子目录内右键图片重置」用例（absPath 必须是子目录路径而非图片路径）。

`browse_history` 不动（folder-level 阅览记录是另一概念，重置阅读进度不重置「最近浏览」）。

Rust 测试 3 个：命中且清三字段 / library 无行返回 false / 有 library 行无 progress 行返回 false。

### E. 喜欢按钮完整 toggle（三入口一致）

**新 Rust 命令** `get_book_status`（放 `src-tauri/src/commands/library.rs`，与 `set_favorite`/`list_library` 同域，共用 D 项提取的 `find_library_id_by_location` helper）：

```rust
#[command]
pub fn get_book_status(
    db: tauri::State<crate::db::Db>,
    source_descriptor: SourceDescriptor,
    abs_path: String,
) -> Result<Option<BookStatus>, String>
// BookStatus { book_id: i64, is_favorite: bool }（serde camelCase → bookId / isFavorite）
```

`list_library` 只回 favorite 行且有分页（默认 100，上限 500），前端匹配不可靠——故必须走精确单查。temp 行（读过但未喜欢）也能查到（`isFavorite: false`）。

**前端（FileBrowser 统一持有状态）**：

- 状态表：`likeStateByPath: Map<locationKey, { bookId, isFavorite }>`，**location key = `descriptorId(descriptor) + '|' + absPath`**（复用 `sourceDescriptor.ts:64` 既有 helper 与惯例键式）——仅以 absPath 为键会跨源串状态（不同源都可能有 `vol1`、根目录 `''`），把 A 源的 bookId/isFavorite 误用于 B 源。切目录清空。查表未命中时调 `getBookStatus` 回填，异步回填完成时校验 location key 仍是当前身份（防切换后旧结果写入）。
- **竞态守卫（审查 P1）**：每个 location key 维护查询 epoch——toggle 写状态时 bump epoch，in-flight 旧查询返回时 epoch 失配即作废，防「点击喜欢前发出的查询在喜欢完成后返回 null 覆盖终态」；喜欢成功后直接写 `{ bookId（addToLibrary 返回值）, isFavorite: true }` 终态，不再回查。
- 三个入口各自按 entry 的 absPath 取状态（工具栏/详情面板用 selectedEntry；右键菜单用 firstItem——右键不一定改变选中）：
  - **工具栏按钮**（`btn-add-to-library`）：`＋ 喜欢`（`reader.like`）↔ `已喜欢`（新 key `reader.liked`）。
  - **EntryDetailPanel**（`entry-detail-add-to-library`）：同二态。
  - **RowContextMenu**（`ctx-add-to-library`）：同二态。
- toggle 行为：未喜欢 → 现有 `readerActions.addToLibrary(entry)` 流程不变；已喜欢 → `setFavorite(bookId, false)`；两条路径后更新状态表对应项 + `onLibraryChanged`（library.refresh）。
- Props/emits：FileBrowser 向 EntryDetailPanel / RowContextMenu 下传「该 entry 的喜欢状态 + toggle handler」；组件不自己发 IPC。

i18n：`reader.liked` zh「已喜欢」/ en "Liked"（`reader.like` 保留）。

测试：Rust `get_book_status` 3 用例（favorite / 非 favorite temp 行 / 无行 null）；FileBrowser 组件测——选中已喜欢目录按钮显「已喜欢」、点击调 `setFavorite(false)` 状态翻转、选中未喜欢目录走 addToLibrary；子组件 props 渲染测。

### I. 瀑布流选中描边环恢复

**回归定位**：选中状态传递链完好（click → select → `is-selected` class，MasonryRow.test 已断言 class 绑定），视觉失效根因初判为 3.0.7 缩略图卡片化——图片从普通流内元素（`width/height:100%`）换成 `position:absolute; inset:0` 铺满卡片的 `MasonryThumbnail` 层后，原选中标识（`outline` + `outline-offset:-2px`）在「绝对定位子层 + `contain: layout`」结构下的绘制层级不再可靠。

**修法（不赌绘制顺序，确定性方案）**：`MasonryRow.vue` 选中标识从 outline 换为置顶 `::after` 环：

```css
.masonry-row::after {
  content: '';
  position: absolute;
  inset: 0;
  border: 2px solid var(--color-accent);
  pointer-events: none;   /* 不挡点击/双击/右键 */
  opacity: 0;
  z-index: 3;             /* 高于缩略图卡片层与角标 */
  transition: opacity 80ms ease-out;
}
.masonry-row.is-selected::after { opacity: 1; }
```

（`.masonry-row` 因 `contain: layout` 自成 stacking context，`::after` 的 z-index 在卡片内部作用，不影响外部。）

- 删原 `.masonry-row.is-selected` outline 规则与 `.masonry-row` 的 `transition: outline`。
- **实机验证**（tauri-devtools 流程，docs/tauri-devtools-debugging.md）：选中卡片确认描边可见、↻ 按钮/角标点击不受 `pointer-events:none` 影响、hover 行为不变；顺带确认回归根因（修复前 outline 是否真不渲染，记录到 spec 或报告）。
- 测试：MasonryRow.test 既有 `is-selected` class 断言保留；新增源码守卫断言（style 块含 `::after` + `pointer-events: none` 规则，项目已有源码守卫测试模式）。

- **I 根因存疑但修法确定性**：即使 outline 实际另有失效原因，`::after` 置顶环在所有绘制顺序解释下均可见；实机验证兜底。
